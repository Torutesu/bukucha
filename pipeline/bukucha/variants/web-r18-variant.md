## 2. 本体との関係(派生アーキテクチャ)

**原則: フォークではなく、同一モノレポからのビルドバリアント。**

```
bukucha (monorepo)
├── packages/core        # チャットエンジン、作成ウィザード、記憶、課金、UGC基盤 — 完全共有
├── packages/ui          # ノベルUI部品 — 共有(テーマ変数のみ差替)
├── apps/main            # 本体: Web+iOS+Android。content_level <= r15(Phase 2でWebのみr18)
└── apps/r18             # 派生: Web専業。別ドメイン・別ブランド。content_level = r18中心
```

本体側で最初から仕込む5点(nsfw-analysis.mdの仕込みリスト)が、そのまま派生の成立条件:
1. コンテンツフラグ3値(`all_ages / r15 / r18`) — 派生はr18を主とするだけ
2. 表現フィルタのサーバー側制御 — 派生はフィルタプロファイルが違うだけ
3. Web直販決済が第一級 — 派生はストア決済を持たないだけ
4. 年齢確認の独立モジュール — 派生は入口ゲート+強い認証に差し替え
5. LLM抽象化レイヤ — 派生はNSFW許容プロバイダにルーティング

**本体と分けるもの**(ブランド防衛と規制隔離):
- ドメイン・ブランド名(本体名を冠しない or 「〜がるまに」式のサブブランドかは要判断)
- 運営主体の表記(可能なら別事業表記。カード会社・ストア審査からの延焼を防ぐ)
- アカウント: [要確認] SSO共有(DMM/FANZA方式: 同一アカウントで両方入れる)か完全分離か。SSO共有は導線として強力だが、本体ストアアプリの審査時に「成人サービスとの一体性」を疑われるリスクがある
- コンテンツDB: 論理分離(同一DB+フラグ)で開始し、審査・法務要請があれば物理分離できる設計に

## 3. 派生固有の要件

### 3.1 入口・年齢確認
- 全ページ手前に年齢確認ゲート(ムーンライト/FANZA方式)。自己申告で入場、**課金時に実効的な成人確認**(カード名義 or 携帯キャリア契約=成人シグナル)
- 検索エンジン向けにR18メタタグ(RTAラベル等)。本体からの直接リンクはストア規約上、アプリ内には置かない(Web版フッター等のみ)

### 3.2 決済(最重要・単一障害点を作らない)
- **Visa/Mastercardを主決済にしない**。構成: JCB + キャリア決済 + 銀行直接決済(DLsiteが2025年に導入した方式) + プリペイド/ポイント中間層
- [要確認] DMMポイント経済圏への相乗り(FANZAキャラチャット方式でポータル参加する選択肢)は、集客と決済を同時に解決するが手数料とプラットフォーム依存を生む
- 通貨は本体と別管理(資金決済法の残高管理も別建て)

### 3.3 LLM
- NSFW生成を規約で許容するプロバイダ/オープンモデル推論ホスティングを選定(大手安価APIは規約上使えない前提)
- [要確認] Stage 2で「モデル×利用規約×日本語NSFW品質×単価」の対照表を作成。候補系統: オープンモデルのRP系ファインチューン(Cydonia等)の日本語品質検証、NSFW許容の商用API
- 品質戦略: R18領域はテンプレ・文体プロンプトの作り込みで大手モデルとの品質差を埋める(女性向けR18は「情緒の文法」が独特で、プロンプト資産自体が堀になる)

### 3.4 表現ガイドライン(カードブランド制約の先回り)
- R18でも不可: 未成年(見た目含む)、実在人物、非同意(レイプ表現)、近親、獣姦 — 国際カードブランド禁止リスト由来。pixiv型の「後出し規制」はコミュニティ信頼を壊すため**最初から明文化**
- 女性向け定番の「強制愛・監禁・オメガバース」との衝突ライン: [要確認] 「同意の演出があるダークロマンス」の線引きを規約でどう書くか。らぶカル/がるまにの現行ガイドラインを参考に法務確認
- 公開前AIチェック(本体§7-6と共通基盤)にR18プロファイルを追加: 禁止リスト検出+二次創作検出

### 3.5 集客(広告不可前提)
- 主戦場はX(成人向けコンテンツをラベル付きで公式許可している唯一の大手)。作品カードの引用ポスト共有機能を最初から
- SEO(「夢小説 R18」「TL 小説 AI」等)、ムーンライト/がるまに文化圏の書き手の招致(初期クリエイター施策)
- 本体(B/C)からの自然流入: Web版フッター・年齢確認済みユーザーへの案内(ストアアプリ内では一切言及しない)

### 3.6 UGC/クリエイター
- 本体と同じシチュエーション作成基盤。R18作品の審査フロー(Zetaアンリミット審査方式: 作品単位+クリエイター成人確認)
- 書き手の出し分け: 同一作品の「寸止め版(本体)/R18版(派生)」ペア公開をサポート(ムーンライト⇔なろう分離の文化に馴染む)
- クリエイター報酬は本体より優先度高め: R18領域は「書き手がどこで書くか」の競争であり、還元率が武器になる(FANBOX R18の12.9%手数料引き上げへの不満は取り込み機会)
