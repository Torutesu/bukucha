# User Requirements (原文ベース) [USER-REQ]

- date: 2026-08-06
- benchmark: https://kyarapu.com/ , https://zeta-ai.io/en

## プラットフォーム方針
- SPファースト。Web + iOS + Android を作る
- PCで見た時も「中央にSPビュー」で表示する作り(PC専用レイアウトは作らない)

## プロダクトの本質(ユーザー定義)
1. 本質はラノベ — 文章体験が中核
2. 文章が連続的に出てくる体験
3. ドーパミンの頻度と量を設計する
4. 没入感
5. 自分で物語の分岐を作れる
6. 「俺が作った最強のシチュエーション」が作れる
7. 妄想が具現化できる
8. ソーシャルバリュー: 書き手を集め続け「そこがいい」となることが優位性
9. Pixiv的なクリエイターコミュニティモデル
10. DMMがエロ領域で同種のことをやっている(市場実証の傍証)
11. **シチュエーションが先、キャラが後。逆はない** — 設計の最重要原則
12. 故に有名IPは不要、むしろ無い方が良い
13. 偶然性(セレンディピティ)型ではなく欲求性(自分の欲望を叶える)型のプロダクト
14. Zetaは月間6億円規模で売れている(市場規模の傍証)
15. IPがいらない

## 導出される設計上の含意(推定を含む)
- チャットUIは「吹き出しチャット」より「ノベル(地の文+セリフ)」寄りに設計すべき [USER-REQ: 本質はラノベ]
- 発見面はレコメンド偶然性より「検索・タグ・シチュエーション起点の欲求充足」を優先 [USER-REQ: 欲求性]
- 作成フローは「キャラ作成」ではなく「シチュエーション作成」を第一階級のオブジェクトにする [USER-REQ: シチュエーションが先]
- 書き手向け機能(公開、ランキング、リアクション、収益化の道筋)が中長期の堀 [USER-REQ: Pixiv的]

## 2026-08-28 更新 [USER-REQ]

- benchmark: **https://ooc.ai/(OOC — The Playable Anime)に一本化**
- market: **北米(US + CA)のみ**

### ユーザー指示(原文)
> 完全にベンチマークをこれにして、マーケットを北米に絞って最適化してやる。この方針で、ドキュメントも、コードも全てやります
> 徹底的にこのサービスの設計やできること、評判や改善点、受けているポイントなどを洗い出して、スーパークローンし、超えられるようにしてください

### 「超える」の定義(teardown §0 の実測に基づく)
OOC の否定レビュー内訳は **金(約69%)+ 記憶(23%)でほぼ全部**。文章品質・世界観・UIへの不満はほぼない。
したがって「超える」= **同等の構造(stat / endings / builder / keyword book)を作った上で、この2点を構造的に解決すること**。

1. **記憶**: Canon Ledger(SCR-024 / AIF-001)— 構造化・永続・ユーザー編集可・**編集は常に無料**
2. **金**: サブスク主・クレジット従。**Free でも Standard モデルは無制限**(OOC は Story Mode を有料壁の向こうに置いている)
3. **クリエイター**: 門なし・1ターン目から収益・**著作権は作者のもの**(OOC は $300 + 2% で恒久譲渡)
4. **発見**: 作品ページを SSR + OGP で公開。北米の需要エンジンは固有名詞検索であり OOC はSPAでそこを捨てている
