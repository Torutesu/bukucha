# Research: 北米のコンテンツ供給側 — 誰が作り、どこから引っ張れるか

- collected: 2026-08-28
- 問い: 「北米は作り手のマーケットが小さいから、最初はオリジナル制作か既存サービスの配信が必要では」[USER-REQ]
- confidence: medium-high(プラットフォーム公表値・契約条項は高 / カタログ件数の一部は三次)

---

## 0. 結論を先に

**「北米の作り手が小さい」は、そのままでは事実ではない。**
Character.AI だけで **ユーザー製ボットが1,800万体以上**存在する。世界最大の作り手プールが北米にある。

小さいのは以下の3つであり、それぞれ対処が違う:

| 実際の制約 | 性質 | 対処 |
|---|---|---|
| **① ローンチ時に我々の作り手はゼロ** | 全プラットフォーム共通のコールドスタート。北米固有ではない | 初期在庫を自前で用意する(ユーザーの指摘は**ここが正しい**) |
| **② 二次創作禁止が供給の大半を切り落としている** | **我々の自社方針の帰結**。1,800万体の大半は二次創作 | 方針を維持するなら供給を別ルートで作る / 方針自体が論点になりうる |
| **③ オリジナルの「インタラクティブ小説」作家は本当に少なく、しかも囲われている** | Choice of Games が独占永久ライセンスで縛っている | ここは諦め、**Web小説作家**に行く(§3) |

つまり **「最初は自前 + 既存からの引き込み」というユーザーの判断は正しい。**
ただし理由は「市場が小さいから」ではなく、**「コールドスタート + 自社の二次創作禁止方針」**である。
市場が小さいなら永久に自前制作だが、実際は大きいので **UGCへの移行は可能** — 順番の問題にすぎない。

## 1. 需要側と作り手側の実サイズ

| プラットフォーム | 規模 |
|---|---|
| **Character.AI** | **ユーザー製ボット 1,800万体以上** / MAU 2,000万 / 平均利用 **75分/日** |
| **Janitor AI** | ユーザー 1,500万 / 公式Androidアプリ 50万DL以上 |
| **Royal Road** | **無料小説 50,000本以上**。Progression Fantasy / LitRPG / Portal Fantasy / **Isekai** が主力ジャンル |
| **OOC** | Google Play 50万DL以上 / 米国 Simulation 売上6位(`ooc.md` §9) |

**Royal Road のジャンル構成が我々のタグ体系とほぼ一致している**ことに注目。
isekai / LitRPG / progression fantasy は seed カタログにもタグマスタにも既に入れてある。

## 2. Lane C: キャラクターカードの取り込み(既存サービスからの引き込み)

### 事実
- **Character Card V2 (`chara_card_v2`) が事実上の標準**。PNG に JSON を埋め込む形式で、
  SillyTavern / Chub Venus / Agnai / RisuAI が相互に読める
- フィールド: `name` / `description` / `personality` / `scenario` / `first_mes` / `mes_example`
- **V3 (`ccv3`)** は後方互換のまま **ネイティブの lorebook 構造**、多言語アセット、作者メタデータを追加
- SillyTavern は既定で両チャンクを書き出すので、1ファイルで新旧クライアントに通る

### 我々のスキーマへの写像(ほぼ1:1で入る)

| Character Card | HEADCANON |
|---|---|
| `name` / `personality` | `Character.name` / `Character.personality` |
| `description` / `scenario` | `Story.worldSetting` / `Intro.introText` |
| `first_mes` | `Intro.firstMessage` |
| `mes_example` | `Character.exampleDialogs` |
| V3 `lorebook` | **`KeywordEntry`**(こちらは同時3件のような上限を持たない) |
| (なし) | `StatDef` / `EndingDef` は AIF-005 で後付け生成できる |

**取り込みは実装として軽い。**そして「SillyTavern から乗り換えたい人」に対する
最も強い一言は「**持っているカードをそのまま持ってきてください**」である。

### ただし衝突する
1,800万体の大半は**二次創作**であり、我々のコンテンツポリシー(オリジナルのみ)と正面から衝突する。
IP リスクも我々が負う。

→ **解: 取り込みは Private / Link only 限定にする。**
「自分のカードを持ち込んで自分で遊ぶ」は許可し、**公開はさせない**。
これは**カタログ戦略ではなく移住ツール**である。供給ではなくユーザー獲得に効く。

## 3. Lane B: 既存 Web 小説の翻案(最有力)

### なぜここか
- **在庫が既にある**。Royal Road だけで5万本、ジャンルが一致
- **作家が囲われていない**(後述の Choice of Games / Webnovel と違う)
- **読者が付いてくる**。作家は既に Patreon 等で自分の読者を持っている
- **我々の AIF-005 が、まさに散文 → 遊べる構造(stat / ending / keyword book)への変換器**である

### 2026年の相場(取れた範囲)
- **12〜24ヶ月の独占開発ウィンドウ付きオプション契約**が主流
- IP ホルダーがバックエンド配分を取る共同製作型も一般的
- Wattpad / Webnovel / Tapas / **Royal Road** が「翻案の転換率が最も高い」IP 供給元とされる
- 参考: 縦型ショートドラマ産業(**$11B**)は**ほぼ全量が Web 小説 IP のパイプライン**で回っている。
  「既存の物語を別フォーマットで配信する」は実証済みのモデルであって、思いつきではない

### 競合の契約条件 = 我々の武器になる部分

| 事業者 | 条件 | 作家から見た問題 |
|---|---|---|
| **Choice of Games / Hosted Games** | ロイヤリティ **25%**、**著作権は作家に残る**が、**独占・永久ライセンス**。Twine / Ren'Py / VN 等の競合フォーマットで同作品を出せない | 条件自体は誠実だが**独占**。ここのカタログは事実上引っ張れない |
| **Webnovel(起点海外版)** | **全世界・独占・永久・取消不能・再許諾可の全著作権ライセンス**。**派生作品の著作権も事業者が持ち**、作家の承認なしに商業利用できる。派生収益のロイヤリティは **10%** | Writer Beware が公式に警告している水準 |
| **OOC Original** | **$300 + レベニュー2%**、**著作権を恒久譲渡**。削除も非公開化も以後できない | 我々が既に §8 で名指しした条件 |

→ **共通点: どれも独占か買い切り。**
我々が既に採用している「**非独占・著作権は作家のもの**」は、
OOC に対してだけでなく **この業界全体に対しての差別化**になる。
翻案ライセンスの交渉材料としてそのまま使える。

## 4. Lane A: 自社オリジナル(コミッション/内製)

- OOC がやっていること。`OOC Original Exclusive Hall` + 専用UI + バッジ(`ooc.md` §7)
- 完全にコントロールできる代わりに、単価と時間がかかる
- **トーンを決める旗艦タイトル**にはこれが要る。カタログ全体をこれで埋めるのは非現実的

## 5. 3レーンの比較

| | Lane A 自社オリジナル | Lane B 既存小説の翻案 | Lane C カードの取り込み |
|---|---|---|---|
| 在庫が既にあるか | ✗ ゼロから | **✓ 5万本規模** | **✓ 1,800万体規模** |
| 読者が付いてくるか | ✗ | **✓ 作家の既存読者** | △(移住してくる本人) |
| 単価 | 高 | 中(オプション + レベニューシェア) | **ほぼゼロ** |
| 立ち上がり | 遅い | 中 | **即日** |
| 二次創作ポリシーとの衝突 | なし | **なし**(オリジナル小説) | **重大**(大半が二次創作) |
| IP リスク | なし | 契約で処理可 | 高 |
| 我々の既存実装で足りるか | ✓(ビルダー) | **✓ AIF-005 が変換器そのもの** | 実装は軽いが**公開制限が必須** |
| 適した役割 | **旗艦・トーン定義** | **カタログ本体** | **移住ツール(獲得)** |

## 6. 示唆: ポジショニングの順番が変わる

現在の実装は「**1ターン目からのレベニューシェア / 著作権は作者のもの**」を3本柱の1つに置いている。
供給がゼロの状態でこれを前面に出しても意味がない。**作り手向けの武器は、読者が居てから効く。**

- **ローンチ時の一文**: 「よく出来た物語が並んでいて、記憶が壊れず、メーターがない」
- **フェーズ2の一文**: 「そして、ここに書くと著作権を手放さずに稼げる」

コード側は既に両方を持っている(`CreatorEarning` / 非独占の Terms)。
**変えるのは実装ではなく、発見面での重み付けと Originals の一級市民化**である。
